The `corpus-client` tool provides direct subcommands to inspect, download, and index corpora:

# 1. Check client version & status
corpus-client --version

# 2. Search available Swecha datasets
corpus-client search --query "swecha-open-docs"

# 3. Pull corpus data to local cache
corpus-client fetch --id swecha-open-docs --out ~/.cache/swecha/

# 4. Start local MCP vector server
corpus-client serve --port 8080
OpenCode MCP Integration Config ~/.config/opencode/opencode.json

How `opencode` connects to `corpus-client` via Model Context Protocol (MCP):

{ "mcp": { "corpus-client": { "type": "local", "command": ["corpus-client", "serve"], "enabled": true } } }

📖 Theoretical Architecture & Principles

1. What is the core principle of corpus-client?

`corpus-client` decouples large knowledge bases from LLM weights. Instead of fine-tuning or re-training a neural network every time documents update, `corpus-client` stores documents as searchable vector chunks. When a user asks a question, it retrieves only the relevant paragraphs and feeds them into the local model's prompt.

2. How does corpus-client connect to models & servers?

It connects via two primary paths:
• Local Vector IPC / MCP Protocol: Serves local JSON-RPC endpoints to AI coding agents like opencode.
• REST API Gateway: Communicates with Swecha's central forge (code.swecha.org) to synchronize licensed datasets.

3. What sequential outputs are generated?

Sequence Order:
1. raw_documents.json — Initial raw text files pulled from repository.
2. token_chunks.json — Text split into 512-character blocks with 50-character overlap.
3. embeddings.bin — Floating point matrix representations of document chunks.
4. augmented_prompt.txt — Final combined query + context passed into local LLM runtime.
